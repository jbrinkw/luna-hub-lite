# Agent API Streaming for Home Assistant Voice Preview

Date: 2026-04-16
Status: Draft — implementation pending
Scope: `apps/mcp-worker` (Cloudflare Worker), `supabase/migrations`, `apps/web/src/pages/hub/AgentPage.tsx`, `docs/`

## 1. Context & Goal

Luna Hub Lite already exposes an OpenAI-compatible agent API at `POST https://mcp.lunahub.dev/v1/chat/completions` (implemented in `apps/mcp-worker/src/openai-compat.ts`). It is consumed by Home Assistant via the `extended_openai_conversation` HACS integration, which in turn drives the Home Assistant Voice Preview Edition (VoicePE) satellite through HA's Assist pipeline.

Today the endpoint accepts `stream: true` but emits **synthetic** SSE — the agentic tool loop runs non-streaming, then the full final text is emitted as a single chunk followed by `data: [DONE]`. Consequences for Voice PE: TTS waits for the entire LLM response before producing any audio. On tool-path utterances ("turn on the kitchen lights") the perceived latency is 2–4 s.

The goal is to make `/v1/chat/completions` stream tokens **as they are generated by Claude** so HA's OpenAI client (and therefore the Assist pipeline) can feed TTS incrementally. A per-user "voice ACK" filler is layered on to cover the silence during server-side tool execution.

## 2. Non-Goals

- Native HA custom_component (HACS integration). Scope is the OpenAI shim only.
- HA-exposed-entity tool passthrough. All tools remain Luna-Hub-side; the endpoint ignores any `tools`/`tool_choice` in the request.
- Model override per request. Claude Haiku 4.5 stays hard-coded.
- Thinking blocks / extended reasoning (Haiku doesn't emit them; handler is defensively written but not exercised).
- Streaming tool_calls deltas to the client.
- `usage` chunk at end of stream.
- AbortSignal plumbing into individual tool handlers (flagged as follow-up).
- Per-user rate limiting beyond Anthropic's own.

## 3. Target Behavior

- `POST /v1/chat/completions` with `stream: true` returns `Content-Type: text/event-stream` and emits OpenAI-shaped SSE chunks **as Claude produces tokens**, across all tool rounds.
- Server-side tool execution is invisible to the client except through keepalive comments.
- When `hub.agent_settings.voice_ack_enabled = true`, if no real text has been emitted within `voice_ack_delay_ms` (default 1200) of stream open, emit a one-shot ACK chunk containing `voice_ack_text` (default `"Working on that… "`). Real text concatenates cleanly afterward.
- When `voice_ack_enabled = false` (default), the endpoint is pure streaming — no filler. Existing non-voice OpenAI SDK clients see a behavioral improvement (multi-chunk streaming) with no filler noise.
- Non-streaming requests (`stream: false` or absent) are unchanged.

## 5. Architecture

### 5.1 Streaming plumbing (Cloudflare Workers)

Use a custom `ReadableStream` (not `TransformStream`) so `cancel()` can hook client disconnect:

```ts
const abortController = new AbortController();
const encoder = new TextEncoder();
const completionId = `chatcmpl-${crypto.randomUUID()}`;
const created = Math.floor(Date.now() / 1000);

const stream = new ReadableStream({
  start(controller) {
    runStreamingLoop(controller).catch(() => {});
  },
  cancel() {
    abortController.abort();
  },
});

return new Response(stream, {
  headers: {
    'Content-Type': 'text/event-stream',
    'Cache-Control': 'no-cache',
    Connection: 'keep-alive',
    ...CORS_HEADERS,
  },
});
```

`runStreamingLoop(controller)` is an async function that:

1. Enqueues the initial role chunk.
2. Arms the ACK timer (if enabled).
3. Arms the keepalive interval (fires `: keepalive\n\n` every 15 s regardless of traffic — simpler than reset-on-write; SSE comments are benign).
4. Runs the agentic tool loop (section 5.3).
5. On normal completion: enqueues finish chunk + `[DONE]`.
6. On error: enqueues error chunk + `[DONE]`.
7. In `finally`: clears both timers and `controller.close()`.

### 5.2 Anthropic SDK integration

Use the SDK's event-emitter pattern (cleaner than raw event iteration; the SDK assembles tool_use input JSON for us):

```ts
const aStream = anthropic.messages.stream(
  { model, max_tokens, system, messages: currentMessages, tools: tools.length ? tools : undefined },
  { signal: abortController.signal },
);

aStream.on('text', (delta: string) => {
  if (!firstTextEmitted) {
    firstTextEmitted = true;
    if (ackTimer) clearTimeout(ackTimer);
  }
  enqueueChunk({ content: delta });
});

const finalMessage = await aStream.finalMessage();
// finalMessage.stop_reason ∈ 'end_turn' | 'tool_use' | 'max_tokens' | 'stop_sequence' | 'refusal'
// finalMessage.content = assembled ContentBlock[] (text, tool_use, thinking)
```

The `on('text')` callback is invoked synchronously as `text_delta` arrives, so `controller.enqueue` happens in wall-clock order. `finalMessage()` resolves once the stream ends; if aborted, it rejects with the abort reason.

### 5.3 Tool-round loop

```
currentMessages = [...initialMessages]

for round in 0..MAX_TOOL_ROUNDS:
  aStream = anthropic.messages.stream(...)
  aStream.on('text', streamingEnqueue)
  finalMessage = await aStream.finalMessage()

  if finalMessage.stop_reason == 'tool_use':
    toolUseBlocks = finalMessage.content.filter(b => b.type == 'tool_use')
    if toolUseBlocks.length == 0: break  # degenerate; Claude stopped with tool_use but emitted no blocks
    currentMessages.push({ role: 'assistant', content: finalMessage.content })
    toolResults = []
    for toolUse in toolUseBlocks (serial):
      execute via executeTool → tool_result block (is_error on failure)
      push to toolResults
    currentMessages.push({ role: 'user', content: toolResults })
    continue

  # end_turn | stop_sequence | max_tokens | refusal
  finishReason = (stop_reason == 'max_tokens') ? 'length' : 'stop'
  enqueueFinish(finishReason)
  enqueueDone()
  return

# Exceeded MAX_TOOL_ROUNDS:
enqueueError('Tool round limit exceeded')
enqueueDone()
```

Serial tool execution matches the existing non-streaming path. Parallel execution is not adopted — a voice-UX micro-optimization that complicates reasoning about tool ordering.

### 5.4 Event → SSE chunk mapping

Base envelope for every data chunk:

```json
{
  "id": "chatcmpl-<uuid>",
  "object": "chat.completion.chunk",
  "created": <unix seconds>,
  "model": "claude-haiku-4-5-20251001",
  "choices": [{ "index": 0, "delta": <delta>, "finish_reason": <null|string> }]
}
```

| Trigger                                                     | `delta`                             | `finish_reason` |
| ----------------------------------------------------------- | ----------------------------------- | --------------- |
| Stream open                                                 | `{"role":"assistant","content":""}` | `null`          |
| SDK `on('text', d)`                                         | `{"content":"<d>"}`                 | `null`          |
| ACK timer fires (no real text yet)                          | `{"content":"<voice_ack_text> "}`   | `null`          |
| `stop_reason == 'end_turn' \| 'stop_sequence' \| 'refusal'` | `{}`                                | `"stop"`        |
| `stop_reason == 'max_tokens'`                               | `{}`                                | `"length"`      |
| Mid-stream error                                            | — (see below)                       | —               |

Error chunk (not a normal completion chunk):

```
data: {"error":{"message":"<msg>","type":"server_error"}}\n\n
data: [DONE]\n\n
```

Terminator (always the last line written):

```
data: [DONE]\n\n
```

Keepalive (every 15 s, SSE comment, OpenAI client ignores):

```
: keepalive\n\n
```

### 5.5 ACK timer semantics

- **Gating**: Only armed when `body.stream === true` AND `voice_ack_enabled === true`. Non-streaming requests never emit ACK.
- **Arm**: right after enqueueing the initial role chunk, before the first `messages.stream()` call.
- **Cancel**: first invocation of `on('text')` clears the timer.
- **Fire**: if the timer fires before any text:
  - Enqueue one chunk with `delta: { content: voice_ack_text + ' ' }` (trailing space always appended for clean concatenation with subsequent tokens).
  - Set `firstTextEmitted = true` so subsequent real text continues normally.
  - Timer is cleared so it cannot fire again.
- **Config**: `voice_ack_delay_ms` clamped 0–5000 by DB CHECK constraint. On DB fetch failure: default to disabled (safer than surprising the user with filler).

Verified scenarios:

| Scenario                                                | Emitted sequence                                                                  |
| ------------------------------------------------------- | --------------------------------------------------------------------------------- |
| Fast direct response (text at 200 ms)                   | role, "Kitchen ", "is ", "on.", finish                                            |
| First round text then tool then text                    | role, "Let me check ", …(silent tool exec), "Done.", finish                       |
| First round pure tool_use, text at 1800 ms              | role, (ACK at 1200), "Kitchen is on.", finish                                     |
| Multi-round tool chain, text only at round 3 at 2500 ms | role, (ACK at 1200), "All set.", finish                                           |
| Slow first-token no-tool (2 s cold path)                | role, (ACK at 1200), "It's sunny and 72.", finish — minor awkwardness, acceptable |

### 5.6 Error path matrix

| Failure                                          | Before SSE open                                          | After SSE open                                                                                                         |
| ------------------------------------------------ | -------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| Auth fails                                       | 401 JSON (unchanged)                                     | n/a                                                                                                                    |
| Anthropic key missing                            | 422 JSON (unchanged)                                     | n/a                                                                                                                    |
| `buildUserTools` throws                          | 502 JSON (unchanged)                                     | n/a                                                                                                                    |
| Voice-ack settings fetch fails                   | use defaults (disabled)                                  | n/a                                                                                                                    |
| `messages.stream()` throws round 0 (401/429/5xx) | SSE open already — emit error chunk + `[DONE]`           | same                                                                                                                   |
| Tool handler throws                              | tool_result `is_error: true`, loop continues (unchanged) | same                                                                                                                   |
| Unknown tool name                                | tool_result `is_error: true`, loop continues (unchanged) | same                                                                                                                   |
| MAX_TOOL_ROUNDS exceeded                         | —                                                        | error chunk + `[DONE]`                                                                                                 |
| Client disconnect                                | —                                                        | `cancel()` → `abortController.abort()` → Anthropic stream aborts; in-flight tool handlers complete (no signal plumbed) |
| Anthropic abort mid-stream                       | —                                                        | silently close (`controller.close()`) without error chunk                                                              |

**Autonomous decision flagged**: once SSE is open, Anthropic 401/429 are translated into streamed error chunks rather than breaking the SSE contract with an HTTP status change. HA's OpenAI client raises `APIError` on `{error: {...}}` chunks; this is the standard OpenAI behavior for stream errors. Non-streaming callers keep their JSON 401/429 path unchanged.

### 5.7 Defensive handling of `thinking` blocks

Haiku 4.5 does not emit thinking deltas, but the SDK's `finalMessage.content` may include `{type: 'thinking'}` blocks on future models. Behavior:

- Not forwarded to the client (OpenAI has no thinking concept).
- Preserved in `currentMessages.push({role: 'assistant', content: finalMessage.content})` so Anthropic's tool-use + thinking invariant is satisfied for the next round.

### 5.8 Settings load: single round trip

Existing RPCs called per request (`get_agent_anthropic_key_admin`, `get_agent_system_prompt_admin`) are consolidated — or a sibling `get_agent_voice_ack_admin` is added — so only one additional RPC is issued when streaming. Ack settings failure falls back to defaults (disabled) rather than failing the request.

## 6. Database Changes

New migration: `supabase/migrations/YYYYMMDD_agent_voice_ack.sql` (filename date set at implementation time).

```sql
ALTER TABLE hub.agent_settings
  ADD COLUMN voice_ack_enabled BOOLEAN NOT NULL DEFAULT FALSE,
  ADD COLUMN voice_ack_text    TEXT    NOT NULL DEFAULT 'Working on that…',
  ADD COLUMN voice_ack_delay_ms INT    NOT NULL DEFAULT 1200
    CHECK (voice_ack_delay_ms BETWEEN 0 AND 5000);

-- Admin RPC: Worker reads via service role, returns three fields.
CREATE OR REPLACE FUNCTION private.get_agent_voice_ack_admin(p_user_id uuid)
RETURNS TABLE(voice_ack_enabled boolean, voice_ack_text text, voice_ack_delay_ms int)
SECURITY DEFINER SET search_path = ''
LANGUAGE sql AS $$
  SELECT voice_ack_enabled, voice_ack_text, voice_ack_delay_ms
  FROM hub.agent_settings WHERE user_id = p_user_id;
$$;

-- User-facing save (follows pattern of save_agent_system_prompt).
CREATE OR REPLACE FUNCTION private.save_agent_voice_ack(
  p_enabled boolean, p_text text, p_delay_ms int
) RETURNS void
SECURITY DEFINER SET search_path = ''
LANGUAGE plpgsql AS $$
BEGIN
  IF p_delay_ms < 0 OR p_delay_ms > 5000 THEN
    RAISE EXCEPTION 'voice_ack_delay_ms must be 0–5000';
  END IF;
  IF length(p_text) > 200 THEN
    RAISE EXCEPTION 'voice_ack_text must be ≤200 chars';
  END IF;
  INSERT INTO hub.agent_settings (user_id, voice_ack_enabled, voice_ack_text, voice_ack_delay_ms)
  VALUES ((select auth.uid()), p_enabled, p_text, p_delay_ms)
  ON CONFLICT (user_id) DO UPDATE
    SET voice_ack_enabled = EXCLUDED.voice_ack_enabled,
        voice_ack_text = EXCLUDED.voice_ack_text,
        voice_ack_delay_ms = EXCLUDED.voice_ack_delay_ms;
END $$;

-- Grant execute to authenticated role.
GRANT EXECUTE ON FUNCTION private.save_agent_voice_ack(boolean, text, int) TO authenticated;
```

Also extend `get_agent_settings()` (read RPC used by the Hub UI) to return the three new columns.

## 11. Autonomous Decisions (flag for review)

1. **In-stream error translation**: Anthropic 401/429 after SSE open → streamed `{error: {...}}` chunk + `[DONE]`, not HTTP status. Standard OpenAI SSE behavior. §5.6.
2. **Serial tool execution**: kept serial (matches existing non-streaming path). Parallel flagged as future optimization, not adopted. §5.3.
3. **ACK text trailing space**: always appended for clean concatenation regardless of input. §5.5.
4. **DB failure fallback**: voice-ack settings fetch failure silently falls back to disabled rather than erroring the request. §5.8.
5. **Keepalive cadence**: fixed 15 s regardless of stream activity; simpler than reset-on-write and SSE comments are ignored by OpenAI client. §5.1.
6. **ACK arm-at-open vs arm-on-first-tool**: chose arm-at-open. Simpler, and covers cold-path latency gracefully. Rare slow-first-token-no-tool cases hear ACK unnecessarily; acceptable. §5.5.
