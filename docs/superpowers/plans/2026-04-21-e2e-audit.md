# E2E Test Coverage Audit — 2026-04-21

**Scope.** Brutal audit of every test layer in luna-hub-lite, focused on the prod-path question: _if someone reintroduced a bug we already fixed, would the suite catch it before prod?_

**Method.** I read each suite's setup files, skimmed representative specs to check fidelity (real Supabase / real API / real DB vs. mock), counted assertion density, and cross-referenced against recent `fix:` commits. Nothing was skimmed "by name" — every fidelity judgement is grounded in code I read.

**No tests were written.** This is an audit. All recommendations are numbered and independent so you can pick one at a time.

## 1. Executive Summary

**Overall health: B+.** The suite is significantly better than typical ~550-line feature repos. You already get:

- **Real Supabase local** for 100% of integration + E2E specs (no `fetch` stubbing above the edge-function boundary).
- A dedicated **production** Playwright config (`playwright.prod.config.ts`) that runs the same specs against hosted Supabase with session injection.
- **pgTAP RLS tests** for most user-scoped tables with `UPDATE … WHERE WRONG_USER` mutation patterns (not just SELECT count).
- **MCP worker tests that spin up real `wrangler dev`** (via `globalSetup`) and hit real Supabase through service-role — so tool results are validated against actual DB mutations.
- **Pi integration tests that drive real handlers with real SQLite** (`init_db(":memory:")` + real `ScaleHandler`), not handler-mock ladder.
- Purpose-built **Realtime** specs (`chefbyte/realtime.spec.ts`, `cross-module/realtime-ui.spec.ts`) that install a probe channel and assert UI re-renders within 10s without `page.reload()`.
- **Parity spec** that runs the same operation through both UI and MCP and diffs DB row shapes.
- **Cross-account contamination test** (`auth-edge.spec.ts` scenario 3) that validates TanStack cache clears on logout.

**Where the gloss cracks** — five concrete risks that could ship to prod today:

1. **Edge-function failure paths are not exercised.** `analyze-product` has tests for quota, auth, CORS, and happy-path OFF lookups against real OpenFoodFacts — but **zero tests** for OFF 503, Anthropic timeout, or JSON-parse failure. The bug fixed in the last week (timeout handling) has no regression guard. Same for `walmart-scrape` (only a CORS preflight test — 39 lines total) and `livetrack-session` (no test file at all).
2. **Five RLS-enabled tables lack cross-user isolation tests:** `coachbyte.timers`, `chefbyte.scale_pairings`, `chefbyte.shelf_event_log`, `chefbyte.live_shelf_devices`, `hub.agent_settings`. They are exercised in other tests but "User B cannot read/write User A's rows" is never explicitly asserted on them at the pgTAP layer.
3. **The offline path has a render-only test, not a behavior test.** `OfflineIndicator.test.tsx` mocks the context and asserts the banner renders. No test puts the app into a real offline state, attempts a mutation, and asserts the write is disabled or the queue handles it correctly.
4. **HA SSRF protection has no test.** The recent "SSRF IPv6 blocklist" fix (commit `12fee23`, `d9752e9`) added defenses against Home Assistant URLs pointing at `169.254.*` / `::1` etc. Grep shows **zero** tests for SSRF inputs. If this regresses, a malicious HA URL could reach internal metadata services.
5. **Walmart quota + SerpApi failures are untested.** `walmart-scrape` is one of the costliest edge functions. Only a CORS preflight is asserted. No test for quota exhaustion, upstream failure, malformed response, or cross-user quota isolation.

**Secondary concerns** (see §5): optimistic-update rollback is untested across the whole app; no test drives DST boundary from the React layer; Pi↔cloud DTO drift has a short-circuit regression test (`test_scale_event_ingress_routes_scale_03_to_single_item_short_circuit`) but **no boundary-schema contract test** between `live_scale` firmware payloads and the Pi's `single_item` Literal — the last one that bit you isn't the only place that can drift.

## 4. Gap Analysis (sorted by risk)

### HIGH risk (corrupts data or leaks cross-user data)

1. **Analyze-product failure paths**. If OFF returns 503, Anthropic times out, or the Haiku JSON fails to parse, the user sees either a stale placeholder or a silent scanner error. The timeout-handling bug shipped last week and **there is no test for it**. Any revert of that fix passes CI.
2. **Walmart-scrape: no quota, no auth, no upstream-failure tests**. Only a CORS preflight (39-line file). The per-user rate limiting mentioned in `docs/apps/chefbyte.md` is uncovered.
3. **`livetrack-session` edge function has zero tests at the edge-function layer** (only exercised via the wizard E2E). If the `/create` / `/pi-update` / `/active` routes regress JSON validation or auth, the wizard test may or may not catch it depending on which path breaks.
4. **HA SSRF**: no test blocks `http://169.254.169.254/` / `http://[::1]/` / private-range URLs. Prod regression would allow metadata leak if a malicious user saves a poisoned `ha_url`.
5. **RLS gaps on 5 tables**: `coachbyte.timers`, `chefbyte.live_shelf_devices`, `chefbyte.scale_pairings`, `chefbyte.shelf_event_log`, `hub.agent_settings`. Current pgTAP suite never asserts "User B cannot read/write User A's rows" on these. If a future migration flips the policy to `USING (true)` they slip through.
6. **MCP OAuth 2.1 flow is untested end-to-end**. Only the API-key path has tests.
7. **`scale_pairings` cross-user event isolation**: shelf-ingest integration test covers one scenario (userA device sending event for userB product → "product not found"), but does NOT cover userA creating a pairing row for a scale_id on userA's device that somehow maps to userB's product.

### MEDIUM risk (UX breakage that reaches prod but does not corrupt data)

8. **Optimistic-update rollback is not tested anywhere**. Every `useMutation` optimistic path is in TanStack Query, but no test asserts "if the mutation fails, the UI rolls back to the server state." A rollback bug would present as ghost rows / ghost counts.
9. **Offline path is a render-only test.** No test puts the app offline and asserts writes are disabled / queue is preserved.
10. **Keyset pagination cursor off-by-one** is query-tested at the shape layer (`coach-history.test.ts`) but not at the cross-page boundary. A regression where `lt(plan_date, cursor)` becomes `lte(...)` would drop or duplicate a row on page-2.
11. **Rest timer DB state machine** is pgTAP-tested and unit-rendered, but no Playwright test runs a full start→pause→resume→finish cycle and asserts the DOM tracks the server state.
12. **Hub Voice Assist UI** has backend streaming tests but no front-end E2E test that types a message, receives tokens, handles a tool `isError:true`, and renders gracefully.
13. **MCP key-rotation-mid-flight**. No test revokes the key while an SSE connection is active and asserts the stream closes cleanly.
14. **Parity spec only covers 6 flows**. The remaining ~40 MCP tools have no parity guard — only behavior-in-isolation tests.
15. **Scanner analyze-product failure via real fn**. `SCN4` uses `page.route` to simulate `ai_degraded`. If the actual edge fn changes its degraded-response shape, the route mock continues to pass but the scanner may break in prod.
16. **Extension `extensions.test.ts` mocks fetch**. If an upstream API changes its response shape (e.g., Todoist v1→v2), the mock tests pass but the live tests (which require env keys and are skipped by default in CI) catch nothing.

### LOW risk (edge cases / polish)

17. **DST boundary is pgTAP-tested but no UI test mounts at 2025-11-02 01:30 America/New_York and asserts the macros/history date labels**. The function is correct; the UI layer's consumption of `day_start_hour` could still drift.
18. **Multi-tenant demo-account contamination**. Demo reset is tested (`contracts/validation.spec.ts`). No test runs two real users + a demo user in parallel and asserts data never bleeds.
19. **Concurrent-tab scenarios** (same user, two tabs, mutation in tab A, assertion in tab B) — only indirectly via Realtime specs.
20. **SSE reconnect on MCP worker** has no test for "client reconnects with same sessionId mid-stream."
21. **Edge function Deno-layer unit tests** are entirely absent. Every edge function is tested via local Supabase HTTP only; internal modules (prompt builders, parsers) are not isolated.
