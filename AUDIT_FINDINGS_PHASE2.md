## What the numbers mean

- **L1 (11 HIGH)** — Real symmetry gaps: `catch_all` has no
  `cloud_pairings_sync`, no `pi_UI_section`, and no
  `weight_sync_to_cloud`; `single_item` has no `auto_register`. These
  match the documented intent in `AUDIT_STRATEGY_MERGED.md §1` row L1.
  Each entry is one queued fix-or-waiver decision.

- **L11 (208 MEDIUM)** — High false-positive rate expected: the
  must/never/always grep is intentionally aggressive so it can't miss
  a real rule. Most hits are advisory prose in `docs/` and the audit
  strategy markdowns themselves. Triage in batches by file: pin the
  ~30-50 real invariants, add the rest to a WAIVERS list inside the
  script, drop noise wording from the docs.

- **L8 (874 MEDIUM)** — Code-comment TODO/FIXME/etc markers across
  `apps/`, `hardware/`, `supabase/`, `packages/`. Triage path: bulk
  port the long-tail into `ignore.md` with dates, fix the small
  number of legit-blockers, expand `WAIVERS` for known-deferred
  files.

- **L2 (2)** — `parity_assert.py self-test` SEEDS asymmetry on
  purpose (mirrors the 1.6-ctn-vs-160.4-g bug). The 2 deltas the
  engine reports prove the diff machinery works. A real-mode run
  against the live harness would reset these counts.

- **L4 (0 / clean)** — Poison-outbox DLQ + FIFO-no-block contract
  passes. Worth re-running after any change to the outbox drainer.

- **L7 (smoke)** — `clock_freeze` end-to-end + meta-import test pass.
  Server-side `private.now_with_freeze()` migration is in place but
  not yet wired into existing functions (deferred per spec).
